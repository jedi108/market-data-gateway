# Протоколы и интеграции

[← Словарь](README.md)

## MCP

Model Context Protocol — открытый протокол, через который AI-агенты
(Claude, Codex, OpenCode) вызывают внешние инструменты. Сервер объявляет
инструменты со схемами входа и выхода, агент их вызывает.

**В проекте:** `gateway-mcp` — read-only MCP-сервер, тонкий клиент шлюза. К
провайдеру сам не ходит, поэтому кеш и бюджет действуют и для агентов.

**Код:** `cmd/mcp`.

## stdio

Стандартные потоки ввода-вывода процесса (stdin/stdout). Транспорт MCP для
локальных агентов: агент сам запускает `gateway-mcp` как дочерний процесс и
общается с ним через его stdin/stdout. Сеть не нужна, порт не открывается.

## Streamable HTTP

Сетевой транспорт MCP: запросы идут HTTP POST на `/mcp`. Нужен удалённым
агентам. В проекте запускается только с [bearer-токеном](#bearer-токен) и
только на [loopback или приватном адресе](#loopback-и-приватный-адрес).

## Bearer-токен

Секрет в заголовке `Authorization: Bearer <токен>`. Кто знает токен — тот
допущен. В проекте токены читаются только из переменных окружения и
никогда не пишутся в логи и конфиг.

## gRPC и protobuf

gRPC — RPC-протокол поверх HTTP/2, protobuf — его бинарный формат сообщений.
Так устроен T-Bank Invest API. Сгенерированные привязки изолированы в
`internal/provider/tbank` — остальной код о protobuf не знает.

## Prometheus-метрики

Числовые показатели в текстовом формате на `/v1/metrics`, которые собирает
Prometheus. В метках нет идентификаторов клиентов, поэтому число временных
рядов ограничено.

## Loopback и приватный адрес

Loopback (`127.0.0.1`) — доступен только с той же машины. Приватный адрес
(RFC 1918: `10.x`, `172.16–31.x`, `192.168.x`) — только во внутренней сети.
Peer API и HTTP-транспорт MCP отказываются стартовать на публичном адресе.
